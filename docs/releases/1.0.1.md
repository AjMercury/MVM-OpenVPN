# MikroTik VPN Manager 1.0.1

Direct IP/domain HTTPS replaces localhost-only installation as the default. With no domain supplied, the wizard detects this server's IPv4 addresses. No deployment IP is hardcoded. The HTTPS listener accepts server interface addresses and the completion screen displays a usable server URL. An optional domain and detected IPv4 addresses are added to the certificate SAN and exact allowed login/CSRF origins.

The installer automatically creates a private, self-signed TLS certificate; no domain or manually supplied certificate is required. Verify the displayed SHA-256 fingerprint before trusting/importing the certificate in your browser. A 365-day certificate is generated; `mvm access` can regenerate it when addresses change or renewal is needed. An existing system-trusted certificate can be selected instead. Plaintext HTTP remains limited to optional loopback mode; network cookies remain Secure/HttpOnly/SameSite Strict and CSRF remains enforced. Firewall/NAT/DNS configuration remains under your control.

## Existing installations

Upgrade without reinstalling, preserving the database, key and credentials:

```bash
curl -fsSL https://raw.githubusercontent.com/AjMercury/MVM-OpenVPN/master/install.sh | sudo bash -s -- --action update
sudo mvm access
```

With no address argument, `mvm access` detects the server IP automatically. You can supply a domain or IP explicitly (`sudo mvm access panel.example.com`). Then open the HTTPS URL it prints, verify the certificate fingerprint and trust/import that certificate. The command takes a verified backup and restores the previous configuration if readiness fails. It does not change firewall rules. Allow the configured TCP port if a host/network firewall blocks it.

Upgrades preserve existing access settings until `mvm access` is run. Menu option 16 configures IP/domain access. Port changes preserve configured origin aliases. The old Development Preview service description is corrected, and update/rollback install the selected release's service unit. Status output no longer uses a pager. Downgrading automatic TLS configuration to a version whose readiness checks do not support it is refused before stopping the current service.

Installation shows its current phase, download progress, database setup and service readiness; passwords and private keys stay hidden. Validation covers server-IP detection, domain/IP login and CSRF/Secure cookies, config-change rollback and verified native HTTPS smoke tests. CI/public publication evidence is recorded after execution. RouterOS VPN automation remains experimental and disabled by default.
