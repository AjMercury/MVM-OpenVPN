# Opt-in disposable RouterOS lab

Status: **NOT RUN**. No live mutation tests are enabled by default, and no router credentials are supplied. The regular test suite uses in-memory fakes and verified HTTPS mock servers only. Use a disposable CHR/dedicated router, out-of-band access and a fresh authorized encrypted backup. Never point this procedure at production.

1. Record exact RouterOS stable build (7.17 baseline and a selected current stable), architecture, model, OS and client versions. Bootstrap trusted HTTPS REST manually and configure only the minimum required permissions. Prepare first static input/forward rules and review raw/mangle/NAT/FastTrack and return routing. Keep other operators out of the lab during mutation/rollback tests.
2. Start the application with exact management `/32` allowlist, valid private CA and writes initially disabled. Create admin, scoped operator, auditor and two separate portal accounts. Verify TLS, password, CSRF, scope and cross-user negative cases.
3. Request a sync; verify version/model/storage/RAM/clock externally. Preview the server with public lab endpoint, non-overlapping subnet, explicit allowed hosts/CIDRs and first-chain anchors. Confirm no router writes occurred.
4. Obtain explicit human authorization for the exact generated resources, then enable writes and apply the preview once. Verify CA/server cert chain and key usages, profile/pool ownership, TLS/cipher settings, rule order and read-back. Resubmit the same job ID; it must not create duplicates.
5. Create a user with automatic reserved IP, a second with an allowed static IP, and reject duplicate username/address/out-of-pool requests. Verify each secret is `service=ovpn`. Confirm names alone do not imply CN/PPP cryptographic identity binding.
6. Export encrypted client material with a separate passphrase. Verify actual `.crt/.key` bytes, exact-size chunk reads and cleanup. Download once as the right portal user; deny another user, an expired link and second consumption. Decode the local QR and confirm it contains only the expected authenticated fragment URL.
7. Import the `.ovpn` into the selected exact client. Supply PPP credentials and key passphrase. Establish tunnel, verify assigned IP, DNS, return routes, allowed destinations and **forbidden destinations denied** using fresh connections. Test TCP/UDP independently, each OS independently. Preserve nonsecret evidence.
8. Disconnect alone: reconnection can occur. Disable-and-disconnect: verify secret is disabled, no active session remains and reconnection fails. Do not mark certificate revocation effective merely because PPP is disabled.
9. Inject definite step rejections for certificate/server/user creation and inspect owned-only compensation. Inject lost responses, storage exhaustion, certificate signing timeout, short file reads and process termination after each intent/resource persistence boundary. Restart: the job must require manual intervention, without duplicate writes or deleting existing resources.
10. Make a WinBox change, sync and confirm drift is flagged without automatic overwrite. Test router reset/replacement identity review. Exercise backup/restore on a separate copy, then explicitly clean up only known owned lab resources after dependency review.

Record every scenario as PASSED/FAILED/NOT RUN with evidence and version. A returned HTTP 200 or passing mock test is insufficient for a live test pass. Promote no platform or production release until the full positive and negative client path succeeds.
