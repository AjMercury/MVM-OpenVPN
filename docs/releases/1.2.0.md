# MVM 1.2.0

- Simplified navigation: one Users menu, with protocols displayed as colored service badges under each identity. Less-used operational pages are grouped under More. Neutral backgrounds replace the previous amber theme; OpenVPN, WireGuard, SSTP, L2TP/IPsec and IKEv2 each have a distinct accent.
- Router registration includes a read-only Test Connection button and automatically connects after saving. Connection status, attempt time and actionable failures remain visible. Authentication, policies, DNS, destination allowlists, untrusted/mismatched/invalid certificates, REST endpoints and unreachable ports have distinct messages, including Persian guidance. Testing an unsaved router does not register it or change RouterOS.
- New shared PPP users can use one username/password across the managed OpenVPN, SSTP and L2TP services on the same router. They use one PPP secret/profile and address policy; when OpenVPN exists, its pool and policy are primary. WireGuard configurations can be attached to that identity through Add Service. Shared-identity disable attempts every linked service and disconnects its PPP sessions.
- Sharing PPP credentials requires the other PPP services to be observable, PPTP/PPPoE to be disabled, and active OpenVPN/SSTP/L2TP listeners to be managed. These checks run again at apply. Additional PPP listeners cannot be provisioned while shared users are active, because that would expand their authentication scope. Create the desired PPP services before shared users. Existing users are not silently converted or given broader access.
- Linked identities must have the same router, username and portal owner. Disabled parent identities prevent new linked enrollments and profile exports. Duplicate already-linked services are omitted from the form.

Local Go tests, vet, formatting, manifests and JavaScript syntax pass. Mock-router tests cover both databases and shared PPP/WireGuard creation, scope changes between preview/apply, grouped disabling, router connection tests, automatic connection on save and authorization. Browser checks cover Persian rendering, grouped user services, inline connection success/failure and the WireGuard form.

RouterOS mutations remain experimental and disabled by default. Real router/client interoperability remains unverified; IKEv2 still requires separate client identity enrollment. The panel's verified HTTPS and destination allowlist requirements are unchanged.

Update using `sudo mvm` → Update, or the documented bootstrap update command. Accounts, database and master key are preserved by the existing update process.
